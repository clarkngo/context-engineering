The context window is a budget, not a scratchpad

Prompt engineering is about phrasing — how you word an instruction so a model follows it. Context engineering is about budget — deciding, out of everything that could go into the window, what actually does: which documents get retrieved, how much conversation history survives, which tool results get kept in full versus summarized, what's cached versus regenerated fresh.

A context window is finite and shared. Every token spent on one thing is a token unavailable for another. Most of the failures teams blame on "the model" — hallucination, contradicting itself mid-conversation, missing an instruction that was buried early in a long prompt, giving a confident answer that was true an hour ago but isn't now — trace back to what was or wasn't in context when the model generated its response, not to a capability gap.

This is a working reference for that decision: recurring patterns for managing the budget, the tradeoff each one makes, and the failure modes that show up when nobody's managing it at all.
